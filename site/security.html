// security architecture

Controls that live in the platform, not in a checklist.

mTLS everywhere

Istio service mesh on every workload cluster. Every pod-to-pod connection is mutually authenticated. Certificates rotated on schedule.

  • Istio sidecar default-injected
  • mTLS enforced via PeerAuthentication policy
  • Cert rotation via cert-manager

Kyverno policy enforcement

Kyverno runs on every cluster with a curated best-practices policy set. Policies validate resource configs, security contexts, and image provenance.

  • Audit mode default
  • Enforce mode when you're ready
  • Custom policies supported

RBAC scoped to the object model

Every API permission maps to a position in the Enterprise → Organization → Application hierarchy. Users get the smallest scope that matches their role.

  • Object-model-aware RBAC
  • Default-deny posture
  • Per-environment isolation

Vault-backed secrets

All secrets (database credentials, API keys, cloud IAM tokens) flow through HashiCorp Vault. Secrets are never in Git. Rotation is scheduled and audited.

  • Vault with Raft storage
  • Per-cluster Vault instances available
  • ExternalSecrets Operator integration

Audit logs to your SIEM

Every API call, every deploy, every policy decision is logged. Logs ship to your SIEM via OpenTelemetry or a direct webhook.

  • OpenTelemetry-native
  • Webhooks for Splunk, Datadog, Sentinel
  • Configurable retention
// data handling

We see what you let us see. Nothing more.

Ybor runs in your cloud accounts. We never store customer application data, customer secrets, or customer source code on Ybor-controlled infrastructure. The control plane manages platform state, not your business state.

// ybor sees

  • Platform metadata: cluster status, deploy timestamps, object-model state
  • Telemetry from platform operators
  • Audit logs you choose to share

// ybor does not see

  • Application data
  • Customer secrets
  • Source code
  • Business records
